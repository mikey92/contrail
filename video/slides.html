The problem

GitHub was built for people taking turns

branch per person→pull request per change→human review→merge
01Agents collide late
Two agents rewrite the same function in separate branches. Nobody finds out until merge time.
02Agents are blind to each other
No agent knows what the others are about to change.
03Review doesn't scale
Nobody reads 300 pull requests a day.
04The why is lost
A merged diff forgets the intent, the plan and the trade-offs behind it.
The protocol

Borrowed from aviation

Issue→IntentA unit of work agents take off with
Branch→FlightIts own repository, forked from trunk with Artifacts
—→ClearanceClaims on functions, not files; overlaps wait in a holding pattern
Pull request→LandingMerged onto trunk, tested in a Dynamic Worker, landed by the runway
Merge conflict→Structured conflictExact hunks and functions, with the flight that caused them
Commit message→ContrailIntent, plan and decisions as a git note; why() for any line
Required reviews→Review by exceptionOnly policy-protected code waits for a human
